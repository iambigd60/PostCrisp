# PostCrisp beta security review — 2026-09-29

## Scope and conclusion

Reviewed the public `iambigd60/PostCrisp` repository at `origin/main` `73ac218` and the beta email-auth branch, including tracked files, all reachable Git history, production dependency advisories, authentication and privileged API paths, and read-only Supabase/Vercel settings. This is a source and configuration review, not a penetration test or a proof that no unknown credential exists. No production secret values were opened, copied, or committed.

**No exposed live API key or unauthenticated backdoor login was found in this review.** A history-wide Gitleaks scan reported one Stripe-looking value in an old CI workflow; it is a 19-character `sk_test_` placeholder, not a usable live key. Public `NEXT_PUBLIC_*` Supabase URL/anon key, app URL, and Sentry DSN are intentional browser configuration. `.env.local` is ignored and absent from this checkout. No tracked private-key, certificate, database, or real env file was found. The scan cannot establish whether an unrecognized/custom secret exists, whether a secret was exposed outside Git, or who owns the masked production keys.

The source has a deliberate admin account-recovery capability that can become an account-takeover path if an admin session is compromised. Production dependencies also have known advisories. Resolve the first two findings before broadly inviting beta users.

## Authentication and authorization observations

- Supabase Dashboard showed Email enabled, email confirmation enabled, Google disabled, and the Before User Created `public.hook_enforce_signup_policy` hook enabled. The live `platform_settings` row was `signup_mode='invite'` and `login_enabled=true`. The hook prevents direct Auth creation from silently bypassing the app's invite form; real signup behavior was not smoke-tested in this review.
- TOTP MFA is available in Supabase. At the review's starting commit, `requireAdmin()` checked user plus profile role only; the beta branch now prepares an AAL2 gate, pending live rollout. Supabase leaked-password protection is enabled. Captcha is off. Session settings have a one-hour JWT expiry, compromised-refresh-token detection on, and no absolute or inactivity timeout. These observations do not prove that existing admins have enrolled MFA.
- The Supabase security advisor returned three informational RLS-without-policy entries for service-only tables and no warnings or errors. A sampled review found admin API routes using `requireAdmin()`, user actions calling `getUser()`, and a guarded same-origin auth callback destination. The route-pattern inventory is not an exhaustive IDOR or business-logic audit of every API method.
- `scripts/rotate-admin-password.mjs` is a local service-role utility with a hidden password prompt and explicit confirmation. It is not a web route; possession of the service-role key would itself be highly privileged.
- Login and signup no longer offer Google or call `signInWithOAuth` in the beta branch. The shared `/auth/callback` stays because email confirmation and future auth methods use it.

## Evidence and limits

- GitHub repository visibility: public; scanned all reachable Git commits with `gitleaks git --log-opts=--all --redact` and reviewed the one placeholder hit without disclosing its raw value.
- In the isolated beta branch, `npm run typecheck` passed, `npm run lint` passed with four pre-existing warnings, and `npm test` passed 301/301 across 32 files. A production build passed with build-only public Supabase URL/key placeholders; a build without these variables failed while prerendering `/auth/reset-password`, so this is not a production-environment validation. The generated `.next/static` files contained none of the searched server-key variable names or Stripe key prefixes. No live auth or API smoke probe was run.
- Inspected tracked files, public assets, env naming/ignore rules, server/client key usage, admin auth and user-management routes, signup/auth callback, middleware, API route inventory, and Vercel/Supabase read-only settings. No live runtime attack probe was run for this review.
- `npm audit --omit=dev` reports lockfile advisories, not confirmed exploitation in PostCrisp. The Windows-specific Next advisory does not by itself establish a risk on Vercel's Linux runtime. The AVIF advisory still warrants a patch; the exact image-processing exposure needs validation.
- Production key values were masked, so this review cannot prove their age, owner, rotation status, or correspondence to the provider accounts shown in earlier screenshots. It cannot certify a deployed JavaScript bundle from source inspection alone.
- Previous Phase 0 recovery, complete current migration-chain reset, live AI generation, WAF-enforcement, and post-hook invite-signup checks remain open. Dennis explicitly deferred the paid restore and billing work.
